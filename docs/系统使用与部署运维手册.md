# 系统使用与生产部署运维手册

> **文档版本**：V1.0  
> **适用对象**：红河数据产业集团党总支组织员、三家子公司党支部书记及组织委员、系统运维工程师

## 第一部分：业务功能使用手册

### 一、 发展党员全流程全生命周期管理（工作台）

#### 1. 查看发展成员档案
- 登录系统后默认进入 **【发展党员全景工作台】**；
- 顶部为 5 大阶段快捷流转航标（01申请入党 ➔ 02积极分子 ➔ 03发展对象 ➔ 04预备党员 ➔ 05转正归档），点击任一阶段即可穿透筛选处于该阶段的发展成员；
- 点击表格任意成员右侧的 **【全景档案】** 按钮，呼出 **【一人一档全景电子档案】** 抽屉。

#### 2. “一人一档”时钟轴与规程办理
- 抽屉左侧展示严格遵循《细则》的 25 项标准化规程时间轴，办结步骤显示绿勾，当前步骤高亮闪烁，未来步骤置灰；
- 点击任意历史或当前步骤，右侧工作台联动切换查看该步骤的政策依据、办理主体及归档材料清单；
- 点击 **【一键套打全套 Word/PDF 材料】**，系统基于成员档案自动完成字段占位符替换，批量生成排版规范的标准 Word/PDF 文档包。

#### 3. 党务合规防错引擎校验与阻断说明
- 点击 **【确认审核并推进至下一步】** 时，系统自动触发合规防错引擎实时体检：
  - **考察期不满 365 天硬阻断**：如积极分子培养不足一年（如张强同志考察仅 290 天），系统弹窗强行阻断流转，杜绝“程序缩水”违规入党；
  - **申请谈话时限预警**：递交入党申请书超 20 天未完成谈话时亮黄色警报；
  - **纪检会签一票否决**：发展对象确定与接收前，未取得集团纪委出具的《廉洁从业审查意见书》前禁止推进；
  - **集中培训 24 学时核验**：未取得党校结业证书前禁止进入预审公示。

### 二、 全集团所有党员花名册管理

#### 1. 党员花名册核心字段透视
- 切换至 **【全集团所有党员花名册】** 标签页；
- 表格完整展现全集团在册党员队伍全貌，重点字段说明：
  - **党龄**：由系统根据入党时间（接收预备党员日期）自动按自然周年精确核算，杜绝人工填报笔误；
  - **原所在党支部**：清晰记录党员转入前所在的原籍支部或发展支部；
  - **转入本支部时间**：党员组织关系转入本支部的法定日期；
  - **组织关系转出**：若已调离转出，红框标明 `已转出至：某支部 (转出日期)`，未转出标明 `在册正常`；
  - **年度集中培训时长**：以 **40 学时** 为达标底线，达到 40 学时显示绿色 `[培训已达标]`，不足 40 学时提示黄色 `[待集中补训]`。

#### 2. 单条新增录入党员
- 点击表格右上角 **【新增党员】** 按钮；
- 填报姓名、工号、身份证号、所属党支部、最高学历、政治面貌、党内职务、入党时间、原所在党支部、转入本支部时间等；
- 表单选择入党时间后，系统自动动态计算党龄；确认后即时录入花名册。

#### 3. 在线修改完善党员档案
- 点击列表右侧任意党员的 **【修改档案】** 按钮；
- 系统完整回显该党员的全部历史信息，可随时补充修改原所在党支部、学时、组织关系转出时间与转出支部名称；点击保存即时生效。

#### 4. Excel 批量模板下载与导入
- 点击右上角 **【批量导入花名册】** 按钮，启动 3 步向导式弹窗：
  1. 点击 **【下载党员花名册导入模板 (.xlsx)】**，获取标准表头模板；
  2. 线下填报后，点击选择本地 Excel 文件上传；
  3. 系统自动解析并校验身份证与工号唯一性，预览解析结果后点击 **【确认批量导入并入库】** 即可完成初始化迁入。

### 三、 党支部“三会一课”与每月主题党日规范台账

#### 1. 组织生活开展情况核查与多维筛选
- 切换至 **【支部“三会一课”与组织生活台账】** 标签页；
- 顶部统计卡片实时反映全集团支委会（36次）、党员大会（12次）、党课（12次）、主题党日（36期）完成情况；
- 筛选栏全面支持**单选与多选复合过滤**：
  - 按党组织（红数信息、幂次科技、链达科技、集团党总支）单选或多选；
  - 按组织生活类型（支委会、党员大会、党课、主题党日）单选或多选；
  - 按议题分类彩色标签（发展党员、政治理论、业务融合、组织建设等）单选或多选。

#### 2. 发起与记录组织生活会议
- 点击右上角 **【记录组织生活会议】** 按钮；
- 选择所属党支部、会议类型、会议主要议题、召开日期、地点、主持人、主讲人及应到/实到考勤人数；
- **动态增加重点研究议题及彩色标签**：
  - 在“主要决议纪实”上方点击 **【增加一项议题】**；
  - 填报具体议题内容，并在后方选择对应的彩色分类标签（如红标“发展党员”、金标“政治理论”、绿标“业务融合”）；单次会议支持添加多项议题；
- 若会议涉及讨论接收预备党员（第18步）或转正票决（第24步），可选择关联发展党员步骤与被讨论成员姓名，实现业务联动；
- 填写主要决议纪实后点击保存入库。

#### 3. 管理员在线修改完善会议记录
- 若开会后需继续补充研究议题、调整出勤人数或完善决议纪实，点击列表行右侧 **【修改】** 按钮；
- 弹窗完整回显原所有字段、议题列表与彩色标签，修改补充后点击 **【保存修改内容】** 即可更新。

#### 4. 会议全套规范附件归档（五类凭证）
- 点击操作列 **【附件管理】** 按钮，呼出附件归档弹窗；
- 下拉选择附件类别：
  - `会议通知`（提前发文留痕）
  - `会议纪要`（讨论与决议正本）
  - `表决决议书`（无记名票决原件）
  - `签到考勤表`（现场亲笔签名扫描件）
  - `现场纪实照片`（党旗下开会佐证）
- 选定本地文件点击 **【确认上传归档】**；表格中支持一键预览下载或删除替换。

#### 5. 管理员自定义新增议题标签
- 点击工具栏 **【管理议题标签】** 按钮；
- 输入新标签名称，在预设红金端庄色板或色盘中选取颜色标记，点击 **【添加标签】** 即可即时生效于全系统。

### 七、 党建通知中心与多渠道触达体系

#### 1. 查看与管理党建通知
- 切换至 **【党建通知中心与多渠道】** 标签页或点击导航栏右上角带红点未读数的 **【通知中心】** 按钮；
- 列表支持多维分类检索：
  - 按通知类型（合规时限预警、转正到期催办、纪检把关通知、三会一课通知、普通业务通知）；
  - 按渠道代码（企业微信、钉钉、106政务短信、系统站内信、内网邮箱）；
  - 按未读/已读状态过滤；
- 支持单条点击【详情】查看留痕与接收回执，点击【已阅】或右上角【全部标记已读】消除红点。

#### 2. 多渠道服务配置与连通性测试
- 顶部卡片直观展现 5 大通知通道（企业微信、钉钉、106短信专网、系统站内信、内网邮箱）的在线启用状态；
- 管理员可随时点击开关快捷【启用/停用】指定渠道；
- 点击 **【参数配置】** 即可在线微调各渠道的 API Key、CorpId、Secret、模板编号及网关地址；
- 点击 **【连通性测试】**，系统向该渠道推送联通验证测试报文，验证网络与授权有效性。

#### 3. 全集团时限红线合规巡检与自动分发
- 点击工具栏右上角 **【执行全集团合规扫描并推送】**；
- 系统合规引擎自动扫描在册发展成员的时间节点：
  - 递交申请超 20 天未完成谈话（30天红线）；
  - 积极分子考察不满 365 天防篡改硬阻断受控监控；
  - 预备期届满前 30 天自动下达转正申请催办；
  - 发展对象第 13 步自动提醒纪委出具廉洁意见；
- 扫描发现的问题即时转化为结构化通知，自动分发到企业微信/短信并留痕。

#### 4. 手动发布党务通知与合规指令
- 点击 **【发送新党务通知】** 按钮；
- 选取通知类别、首选触达渠道、接收对象类型（全员广播、指定角色、指定具体党员）；
- 填写通知标题与正文要求，点击发送即可完成跨渠道即时触达。

### 八、 党务用户体系与细粒度四级权限控制 (RBAC)

#### 1. 党务四级角色权限透视
- 切换至 **【党务用户与权限体系】** 标签页（**仅限超级管理员可见**）；
- 顶部卡片清晰展示系统精简清晰的 4 类权威党务角色定位与在册人数：
  - **超级管理员 (`SYS_ADMIN`)**：拥有全平台所有权限，唯一独占管理党务账号与配置多渠道通知参数；
  - **党总支管理员 (`GENERAL_BRANCH_ADMIN`)**：拥有总支本级及直管三家支部的全部党务业务权限，独享第20/25步集体审批批复权；
  - **支部管理员 (`BRANCH_ADMIN`)**：拥有本支部日常发展规程推进、名册维护、组织生活记录与删除，**表单所属支部自动回显锁定且禁用修改**；
  - **普通在册党员 (`PARTY_MEMBER`)**：拥有个人成长全景档案查阅与待办通知接收权限（只读模式）。

#### 2. 新建党务账号与角色指派
- 点击 **【新建党务用户】** 按钮；
- 输入登录用户名（小写英文）、真实姓名、企业工号、联系电话、所属党组织并选择初始党务角色；确认即可建档入库，默认初始密码为 `123456`；
- 点击表格任意用户右侧的 **【授权】** 按钮，即可在线为其调整切换所属 RBAC 角色权限。

#### 3. 启停用与安全冻结
- 点击表格操作列 **【停用/启用】** 按钮，可随时对离职调离人员账号进行权限冻结或解封。

## 第二部分：生产部署与运维手册

### 一、 运行环境要求

| 环境组件 | 最低配置要求 | 推荐配置 | 备注说明 |
| :--- | :--- | :--- | :--- |
| **操作系统** | Linux (CentOS 7.9+ / Rocky Linux 9 / Ubuntu 22.04) 或 Windows Server | Rocky Linux 9 / Ubuntu 22.04 LTS | 64 位操作系统 |
| **CPU / 内存** | 2 核 CPU / 4GB 内存 | 4 核 CPU / 8GB 内存 | 轻量无 Redis 负担，低配即可流畅运行 |
| **磁盘空间** | 50GB 可用存储空间 | 200GB+ SSD 存储 | 用于存放备份与附件文档 |
| **容器引擎** | Docker 24+ & Docker Compose v2+ | Docker Engine 最新稳定版 | 支持容器化全自动一键编排 |
| **Java 运行环境** | OpenJDK 21 LTS | Eclipse Temurin JDK 21 | （容器化部署无需宿主机安装） |
| **数据库** | PostgreSQL 14+ | PostgreSQL 15 Alpine | （容器化部署自带自动初始化） |
| **Web 网关** | Nginx 1.20+ | Nginx 1.24+ Alpine | （容器化部署自带反向代理） |

### 二、 Docker Compose 生产级一键容器化部署 (推荐首选)

系统提供全套 `docker-compose.yml` 编排配置，将 **PostgreSQL 15 数据库、Spring Boot 3 业务后端、Vue 3 + Nginx 前端** 封装为自闭环容器集群。

#### 1. 一键启动部署

**Linux 生产服务器环境：**
```bash
# 赋予执行权限并运行一键脚本
chmod +x docker-deploy.sh
./docker-deploy.sh
```
或直接通过 Docker Compose 命令后台构建运行：
```bash
docker compose up -d --build
# 或旧版本命令: docker-compose up -d --build
```

**Windows 运维环境：**
直接双击根目录下的 **`docker-deploy.bat`** 即可自动构建并后台启动。

#### 2. 容器集群编排与持久化机制
- **数据库容器 (`party-postgres-db`)**：
  - 首次启动自动读取并执行挂载的 `docs/schema-pg.sql` 脚本，全自动完成 16 张数据表、外键约束、索引和种子数据的初始化；
  - 数据存储于命名卷 `party_pg_data`，容器销毁重建数据不丢失。
- **后端服务容器 (`party-spring-backend`)**：
  - 自动通过内部网络 `party-network` 连接数据库，等待数据库健康探针通过后启动；
  - 附件材料持久化存储于卷 `party_uploads_data`。
- **前端服务容器 (`party-vue-frontend`)**：
  - 基于 Alpine Nginx 镜像，提供 SPA 静态托管，并在 `/api/` 路径自动反向代理流量至后端容器。

#### 3. 访问与常用维护命令
- **访问地址**：`http://服务器IP:80`
- **查看运行状态**：`docker-compose ps`
- **查看实时日志**：`docker-compose logs -f`
- **停止所有服务**：`docker-compose down`
- **重启集群**：`docker-compose restart`

### 三、 传统物理机/虚拟机无容器原生部署 (备选方案)

若生产环境受限无法使用 Docker，可采用传统的 Systemd + 本地安装部署方案：

#### 1. 数据库初始化
1. 连接本地 PostgreSQL 实例，创建业务数据库与专用账号：
```sql
CREATE USER party_user WITH PASSWORD 'YourStrongPassword123';
CREATE DATABASE honghe_party_db OWNER party_user;
GRANT ALL PRIVILEGES ON DATABASE honghe_party_db TO party_user;
```

2. 执行初始化 DDL 与种子数据脚本：
```bash
psql -U party_user -d honghe_party_db -f docs/schema-pg.sql
```

#### 2. 后端服务编译与运行

#### 1. 修改生产配置文件
编辑 `backend/src/main/resources/application.yml`（或通过外部环境变量传入）：
```yaml
server:
  port: 8080
  servlet:
    context-path: /api

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/honghe_party_db?currentSchema=public&useUnicode=true&characterEncoding=utf-8
    username: party_user
    password: YourStrongPassword123

party:
  storage:
    type: local
    local-path: /data/party_uploads   # 生产环境物理存储挂载路径
  jwt:
    secret: HongheDataIndustryGroupPartyBuildingSecretKey2025ForSOEPartyMember
```

#### 2. Maven 打包
```bash
cd backend
mvn clean package -DskipTests
# 生成 target/party-building-backend-1.0.0.jar
```

#### 3. 配置 Systemd 后台自启服务
创建服务文件 `/etc/systemd/system/party-backend.service`：
```ini
[Unit]
Description=Honghe Party Building Management Backend
After=network.target postgresql.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/alinkdj/backend
ExecStart=/usr/bin/java -Xms512m -Xmx2048m -jar /opt/alinkdj/backend/party-building-backend-1.0.0.jar
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
启动并开启开机自启：
```bash
systemctl daemon-reload
systemctl enable party-backend
systemctl start party-backend
systemctl status party-backend
```

### 四、 前端生产构建与 Nginx 反向代理配置

#### 1. 前端构建
```bash
cd frontend
npm install
npm run build
# 生成 dist 目录静态资源
```

#### 2. Nginx 配置文件示例
编辑 `/etc/nginx/conf.d/party.conf`：
```nginx
server {
    listen 80;
    server_name party.honghedata.com; # 替换为企业实际域名或内网IP

    # 前端静态页面托管
    location / {
        root /opt/alinkdj/frontend/dist;
        index index.html index.htm;
        try_files $uri $uri/ /index.html;
    }

    # 后端接口反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 50m; # 支持大附件上传
    }
}
```
重载 Nginx 配置：
```bash
nginx -t && nginx -s reload
```

### 五、 存储与数据备份运维策略

1. **附件存储目录管理**：
   - 生产环境中需确保 `party.storage.local-path` 指向独立数据盘或挂载的 NAS 网络存储（如 `/data/party_uploads`）；
   - 定期核查磁盘剩余空间，确保目录具备读写权限（`chmod 755 -R /data/party_uploads`）。
2. **PostgreSQL 自动化日常备份策略**：
   编写每日定时备份脚本 `/opt/backup/backup_pg.sh`：
   ```bash
   #!/bin/bash
   BACKUP_DIR="/data/backup/postgres"
   DATE=$(date +%Y%m%d_%H%M%S)
   mkdir -p $BACKUP_DIR
   pg_dump -U party_user -d honghe_party_db -F c -b -v -f "$BACKUP_DIR/party_db_$DATE.dump"
   # 保留最近 30 天备份
   find $BACKUP_DIR -name "party_db_*.dump" -mtime +30 -exec rm -f {} \;
   ```
   配置 Crontab 每天凌晨 2:00 自动执行：
   ```bash
   0 2 * * * /bin/bash /opt/backup/backup_pg.sh > /dev/null 2>&1
   ```
