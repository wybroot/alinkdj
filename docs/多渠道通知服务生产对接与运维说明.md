# 多渠道通知服务生产对接与运维说明

系统通知模块包含 5 个渠道（系统站内信、企业微信、钉钉、阿里云短信、邮件 SMTP），已按生产对接要求重构为真实协议调用与严格鉴权。

## 1. 架构与安全原则

1. **凭据零入库、零回显**：所有外部渠道密钥（Secret、Key、密码等）必须通过宿主机/容器环境变量提供，后台与数据库仅配置环境变量名称（例如 `PARTY_NOTICE_WECOM_SECRET`），API 接口绝不回传密钥明文。
2. **生产鉴权强隔离**：通知渠道参数配置属于超级管理员（`SYS_ADMIN`）专属权限；通知发送属于党总支及以上管理员（`GENERAL_BRANCH_ADMIN`）；普通党员登录后仅能查阅本人在册通知。
3. **真实协议直连**：
   - **企业微信**：对接自建应用 `POST /cgi-bin/message/send`，自动获取、内存缓存与失效续期 `access_token`；
   - **钉钉**：对接新版 OAuth2 获取 `access_token`，下发 `POST /topapi/message/corpconversation/asyncsend_v2` 异步工作通知任务；
   - **阿里云短信**：集成官方 SDK `com.aliyun:dysmsapi20170525`，严格校验 11 位大陆手机号，按通知类型匹配已审核的模版与变量映射；
   - **邮件**：基于 Spring Mail 与 Jakarta Mail，支持 SSL（465）和 STARTTLS（587），严格校验单发目标与主题安全；
   - **站内信**：直接写入系统持久化数据库并关联账号，支持已读/未读状态流转。
4. **状态与回执诚实呈现**：外部渠道返回成功仅代表“服务商已受理请求”，界面明确提示“最终送达以服务商回执为准”；对于网络超时、未知状态明确标记为“结果待确认”，严禁自动盲目重试产生资费或重复轰炸。

## 2. 环境变量配置清单（生产部署必备）

在生产宿主机或 Docker Compose 运行环境的 `.env` 中配置以下变量：

```bash
# 系统 JWT 签名密钥（生产环境必须设置至少 32 字节的高强度随机串）
PARTY_JWT_SECRET=HongheDataGroupSmartPartyBuildingSecretKey2026ProductionSecure!

# 企业微信应用消息密钥
PARTY_NOTICE_WECOM_SECRET=your_wecom_corp_secret_here

# 钉钉工作通知微应用密钥
PARTY_NOTICE_DINGTALK_SECRET=your_dingtalk_client_secret_here

# 阿里云短信 AccessKey 凭证
PARTY_NOTICE_SMS_KEY_ID=your_aliyun_access_key_id_here
PARTY_NOTICE_SMS_KEY_SECRET=your_aliyun_access_key_secret_here

# 国企邮件 SMTP 授权码/专用密码
PARTY_NOTICE_SMTP_PASSWORD=your_smtp_authorization_code_here
```

## 3. 各渠道后台配置字段与参数规范

### 3.1 企业微信应用消息 (`WECHAT_WORK`)
- `corpId`：企业微信管理后台“我的企业”最下方的企业 ID；
- `agentId`：自建应用 AgentID（正整数）；
- `secretEnv`：固定填写 `PARTY_NOTICE_WECOM_SECRET`。
- *接收人规范*：必须是通讯录中的成员 UserID（单人或以 `|` 分割的多人，单次最多 1000 人）。

### 3.2 钉钉工作通知 (`DINGTALK`)
- `corpId`：钉钉开发者后台组织 ID；
- `clientId`：钉钉微应用的 AppKey / ClientID；
- `agentId`：微应用 AgentID（正整数）；
- `clientSecretEnv`：固定填写 `PARTY_NOTICE_DINGTALK_SECRET`。
- *接收人规范*：必须是钉钉用户 UserID（以逗号 `,` 分割，单次最多 100 人）。

### 3.3 阿里云短信 (`SMS`)
- `provider`：固定为 `ALIYUN`；
- `signName`：阿里云短信服务控制台已审核通过的短信签名（如：`红河数据集团`）；
- `accessKeyIdEnv`：固定填写 `PARTY_NOTICE_SMS_KEY_ID`；
- `accessKeySecretEnv`：固定填写 `PARTY_NOTICE_SMS_KEY_SECRET`；
- `templateJson`：需在配置页按业务场景映射已审核模版，例如：
  ```json
  {
    "DEADLINE_WARNING": {
      "templateCode": "SMS_460012345",
      "parameters": { "name": "receiverName", "item": "title" }
    },
    "REGULAR": {
      "templateCode": "SMS_460012346",
      "parameters": { "title": "title", "content": "content" }
    }
  }
  ```
- *接收人规范*：标准 11 位中国大陆手机号码（如 `13987301005`）。

### 3.4 邮件通知（SMTP） (`EMAIL`)
- `host`：SMTP 服务器域名（如 `smtp.exmail.qq.com` 或内网邮件网关）；
- `port`：通常 SSL 为 `465`，STARTTLS 为 `587`；
- `security`：可选 `SSL` 或 `STARTTLS`；
- `username`：SMTP 登录账号；
- `from`：发件人邮箱（通常与 username 一致）；
- `passwordEnv`：固定填写 `PARTY_NOTICE_SMTP_PASSWORD`。

## 4. 数据库升级说明

对于已有数据库，请在维护窗口执行增量脚本：
```bash
psql -h <db_host> -U <db_user> -d honghe_party_db -f docs/migrations/20261010-notice-production.sql
```
该脚本将：
1. 为 `sys_user` 补充企业微信、钉钉工号字段；
2. 为 `sys_notice_log` 增加服务商回执 ID 与防重键（`dedupe_key`）；
3. 将旧的明文/测试凭据渠道停用，清理不符合生产规范的模拟数据。
