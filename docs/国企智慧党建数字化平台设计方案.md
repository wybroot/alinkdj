## 一、 系统建设背景与企业党建核心定位

红河数据产业集团有限公司作为地方骨干国有数据产业投资与运营平台，肩负着推动数字经济转型、数据要素安全流通、数字基础设施运营的重要使命。坚持党的领导、加强党的建设是我国国有企业的“根”和“魂”。

针对国企基层党建政治性强、业务领域广、程序严密、问责严格的特点，结合以往党建迎检与巡视巡察中常见的“发展程序时序倒挂”、“党员组织关系档案不齐”、“三会一课台账零散”、“集中培训时长不达标”等基层痛点，本平台不再局限于单纯的发展党员单一环节，而是构建为涵盖**党员发展规程严控、在册党员花名册中台、“三会一课”规范台账、荣誉表彰与纪律处分、25步标准文书套打、多渠道通知触达（企微/钉钉/短信/邮件/站内信）、细粒度四级RBAC权限以及数字化调度指挥大屏**为一体的国企智慧党建综合数字化管理中枢。

### 1. 发展党员全流程合规管控与一人一档
- **25步可视化时钟轴**：清晰展现发展成员已完成、正在进行、未开始的步骤节拍；
- **党务合规防错引擎（Hard Blocking Rule Engine）**：
  - *硬阻断*：积极分子考察不满 365 天系统强制锁定，严禁流转至第 9 步（彻底杜绝考察缩水）；
  - *临期预警*：递交申请书超 20 天未谈话黄色警报（30天红线）；预备期满前 30 天自动下达转正申请催办指令；
  - *纪检把关一票否决*：第 13 步未取得纪委《廉洁从业意见书》严禁接收；
- **材料一键套打**：个人信息一次录入，自动合成规范 Word/PDF 表格档案，支持打包导出。

### 2. 全集团所有党员花名册（党籍与组织关系中台）
- **党龄自然计算规则**：取消人工填报，系统根据入党日期按周年精准计算，杜绝笔误与篡改；
- **组织关系闭环跟踪**：包含【原所在党支部】、【转入本支部时间】、【转出本支部时间】、【转出目标支部】；
- **年度集中培训时长**：严格按中央规划，**设定 40 学时为达标红线**，低于 40 学时亮黄色警示；
- **初始化录入双轨制**：支持在线单条精准录入，支持下载标准 Excel 导入模板批量解析导入（自动排重与组织匹配）。

### 3. 党支部“三会一课”与每月主题党日台账管理
- **四类会议全要素纪实**：覆盖支委会、支部党员大会、党课、主题党日；
- **重点研究议题与彩色标签体系**：
  - 支持在会议决议上方动态增加多行研究议题；
  - 预设彩色分类标签（发展党员、政治理论、业务融合、组织建设、党风廉政、群团推优）；
  - **支持管理员在线新增自定义标签与颜色拾取**；
  - 表格筛选引擎支持党支部、会议类型、议题标签的**单选与多选复合精准过滤**；
- **全套证据链附件管理（五类归档）**：
  - 会议通知（发文留痕）
  - 会议纪要原件（讨论过程与决议）
  - 表决决议书（无记名票决汇总）
  - 签到考勤表（现场签名扫描件）
  - 现场纪实照片（党旗下开会佐证）
- **管理员在线修改完善**：支持随时调取已有会议记录，继续补充研究议题、调整出勤、更新决议纪实。

### 4. 组织与个人奖惩/荣誉台账专题
- **双分类维度**：
  - 类别：【组织奖惩/荣誉】 vs 【个人奖惩/荣誉】
  - 性质：【荣誉表彰】 vs 【纪律处分 / 诫勉批评】
- **归档要素**：表彰或处分名称、获奖/受处分主体（支部或党员个人）、级别（国家级、省部级、州级/市级、集团级、支部级）、决定单位、文号、日期、主要事迹与处分事实；
- **增删改查闭环**：支持多维筛选、在线登记、修改、删除及 Excel 报表导出。

### 5. 25步全景文档模板双轨制
- 内置 25 份符合《细则》的标准空白 Word 模板；
- 支持管理员导入企业红头定制模板；套打时优先使用企业版本，支持随时一键恢复系统官方默认版本。

### 7. 党建通知中心与多渠道触达体系（企业微信 / 钉钉 / 阿里云短信 / 邮件 / 站内信）

#### (1) 策略模式解耦与微服务可扩展架构
系统坚决杜绝“各通道同质化”，后端采用 **策略模式（Strategy Pattern）与工厂注册机制（`NoticeChannelFactory`）**，定义顶层通道接口 `NoticeChannelHandler`，为每种第三方服务定制专门的报文协议封装与校验机制：
```
                       ┌─────────────────────────┐
                       │  NoticeDispatchService  │ (业务通知调度中枢)
                       └────────────┬────────────┘
                                    │ 获取对应处理器
                                    ▼
                       ┌─────────────────────────┐
                       │  NoticeChannelFactory   │ (渠道策略工厂)
                       └────────────┬────────────┘
         ┌──────────────┬───────────┼───────────┬──────────────┐
         ▼              ▼           ▼           ▼              ▼
 ┌──────────────┐┌──────────────┐┌───────────┐┌───────────┐┌──────────────┐
 │  WeChatWork  ││   DingTalk   ││    Sms    ││   Email   ││    InApp     │
 │ChannelHandler││ChannelHandler││  Handler  ││  Handler  ││ChannelHandler│
 └──────┬───────┘└──────┬───────┘└─────┬─────┘└─────┬─────┘└──────┬───────┘
        ▼               ▼              ▼            ▼             ▼
   企业微信OpenAPI   钉钉开放平台   阿里云短信SDK 内网SMTP服务  系统站内信红点
```

#### (2) 各通道真实协议封包与生产对接规范
1. **企业微信应用消息 (`WeChatWorkChannelHandler`)**：
   - 依赖凭据：`corpId`, `agentId`, `secretEnv`（引用宿主环境变量 `PARTY_NOTICE_WECOM_SECRET`）；
   - 消息协议：对接 `https://qyapi.weixin.qq.com/cgi-bin/gettoken` 与 `/cgi-bin/message/send`，自动完成 `access_token` 的获取与内存缓存刷新；
   - 消息体：构造标准 `text` 结构体，支持定向推送到成员 UserID，严禁未受控广播；
   - 接口留痕：解析服务商返回的 `msgid`，对包含 `invaliduser` 等字段的响应准确标记为“部分受理”。
2. **钉钉工作通知 (`DingTalkChannelHandler`)**：
   - 依赖凭据：`corpId`, `clientId`, `agentId`, `clientSecretEnv`（引用 `PARTY_NOTICE_DINGTALK_SECRET`）；
   - 消息协议：对接新版 OAuth2 获取 `access_token`，封包标准文本报文下发 `/topapi/message/corpconversation/asyncsend_v2` 异步工作通知任务；
   - 接口留痕：解析钉钉异步任务编号 (`task_id`)，明确标明“服务商已受理，不等同最终送达”。
3. **阿里云短信服务 (`SmsChannelHandler`)**：
   - 依赖凭据：官方 SDK（`com.aliyun:dysmsapi20170525`），配置 `signName`（已审核签名）、`accessKeyIdEnv`、`accessKeySecretEnv`；
   - 业务校验：执行严格 11 位合法中国大陆手机号正则校验 (`^1[3-9]\d{9}$`)；
   - 模版映射：按通知类型（如 `DEADLINE_WARNING`、`TRANS_PROBATION`）灵活匹配阿里云已审核通过的 `TemplateCode`，并按规范替换参数变量；
   - 接口留痕：记录阿里云短信返回的唯一回执编号 (`BizId`)。
4. **邮件通知（SMTP） (`EmailChannelHandler`)**：
   - 依赖凭据：`host`, `port` (465 SSL 或 587 STARTTLS), `username`, `from`, `passwordEnv`；
   - 业务校验：RFC 标准邮箱正则校验，基于 Spring Mail 与 Jakarta Mail 构造合规邮件报文并校验服务器 TLS 证书；
   - 接口留痕：记录由邮件服务器颁发的 SMTP Message-ID。
5. **平台内置站内信 (`InAppChannelHandler`)**：
   - 基于系统数据库持久化，由调度服务直接写入，支持用户维度的已读/未读状态管理与角标联动。

#### (3) 凭据零入库与生产防重发机制
- **凭据零入库、零回显**：所有外部渠道的核心密钥、密码一律由服务器环境变量注入，数据库和前台配置仅保存变量名；
- **自动防抖动与去重**：自动合规扫描引入 `dedupe_key` 唯一索引（`type:memberId:recipientId:date`），同类预警每天每人只分发一次，网络异常时标记为“结果待确认”，杜绝盲目重发。

## 五、 技术架构与轻量化工程设计

### 1. 架构总原则：高可用、轻量化、易运维、零外部中间件依赖

针对企业内部使用场景（全集团党员数十至数百人，并发极低）：
1. **数据库**：选用企业级高可靠关系型数据库 **PostgreSQL 14+**；
2. **免 Redis 架构**：鉴权采用**无状态 JWT Token**，系统字典与配置直接查库或利用 Spring 本地内存缓存（响应时间微秒级），无需部署维护 Redis 服务；
